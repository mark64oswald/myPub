1. System architecture

Five layers, all running locally. Claude Code orchestrates everything through Skills, commands, and MCP servers. The extraction pipeline uses sub-agents covered by the Max subscription — no incremental API cost.

Agent harness Retrieval Storage Extraction Sources (books) Sources (live docs)

2. Data model — knowledge graph

The core data model shows symmetry between books and live documentation. Both feed into the same concept graph through the polymorphic source_type/source_id pattern on concept_relation and procedure. The concept_doc_link bridge table connects concepts to their live documentation sources. Entity resolution via concept_alias keeps the graph cohesive.

3. Data model — Skills Factory

The output side of the system. A skill_package contains multiple skills, each with full provenance tracking through skill_source. Dropped sources are preserved with weight=0 and a drop_reason, making every generated Skill auditable and regenerable.

4. Ingestion pipeline

Books and live documentation enter through parallel paths that converge at the extraction and entity resolution steps. The same extractors, same resolution logic, and same graph tables are used for both — a chapter and a doc section are structurally equivalent from the graph's perspective.

5. Entity resolution flow

The load-bearing integration mechanism. Every candidate concept from extraction — whether sourced from a book chapter or a live doc section — passes through this three-stage matching before being written to the graph. This is what keeps "Change Data Capture" from a Kleppmann chapter and "CDC" from a Zippy README converging on the same concept node.

6. Interactive query flow

How a user question moves through the system. The auto-discovery branch fires when a query references an unknown technology, with a confidence gate that prefers asking the user over ingesting uncertain content.

7. Skills Factory pipeline

The generation-mode flow. Ranking runs silently — no "some sources say" hedging. The output is a coherent, confidently actionable Skills package. Three source-selection strategies handle different domain characteristics.

8. Proactive refresh and priority tiers

Doc sources are refreshed proactively on a schedule to keep interactive query latency low. Priority is driven by actual query patterns, graph centrality, and source volatility. A macOS LaunchAgent runs overnight, handling the non-LLM steps (fetch, hash, embed, index). The LLM-dependent steps (extraction) run on next interactive use via sub-agents.

9. Generator framework

The Skills Factory's seven-stage pipeline is generalized into a framework with pluggable components. Each generator provides its own decomposer (how to break down the domain), output template (what shape the output takes), and validator (what correctness means). The pipeline orchestration — retrieve, rank, merge, generate, track provenance — is shared infrastructure.

10. Eight generators at a glance

Each generator is a different lens on the same knowledge graph. The left column shows what it produces and who consumes it. The right column shows the key architectural choice: which decomposer it uses and whether ranking runs silently or surfaces conflicts.

11. ADR and tech assessment flow

Both are evaluation-oriented generators that use CONTRASTS_WITH edges to find real alternatives. ADRs compare options to make a decision; assessments deep-dive one technology. They share the interactive ranking mode and the practice of surfacing tensions, but decompose differently.

12. Dialog generator with character system

The most architecturally novel generator. Characters are view functions over the ranking engine — each character has a weight profile that biases which sources they draw from. When they disagree in dialogue, the disagreement traces to actual source-ranking differences. The Architect sees the same retrieval results but weights authority higher; the Practitioner weights recency higher. Their debate is real because the underlying sources genuinely disagree.
